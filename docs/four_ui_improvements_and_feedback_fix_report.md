### Change 3: Fix Student Feedback Submission Error
- **Target Files:**
  - `frontend/src/components/MessageBubble.tsx`
  - Backend daemon execution configuration (`127.0.0.1:8000`)
- **Root Cause Analysis:**
  1. **Sandbox Loopback Isolation (Root Cause A):** On Windows, background daemon tasks started inside the standard command sandbox (`BypassSandbox: false`) restrict socket binding and loopback connections from external browser sessions and the host OS (`WinError 10061: No connection could be made because the target machine actively refused it`).
  2. **Generic Exception Masking (Root Cause B):** In `MessageBubble.tsx`, the `try / catch` blocks for both `handleThumbsUp` and `handleSubmitNegativeFeedback` previously caught all errors blindly without reading the exception payload and hardcoded the error notification:
     ```tsx
     // Before
     } catch {
       onNotify?.("Failed to record feedback. Please check your network.", "error");
     }
     ```
     This masked all actual server validation codes (e.g. 400 Bad Request, 422 Validation Error) or specific connectivity diagnostics generated by `normalizeApiError()`.
- **Fixes Implemented:**
  1. Updated `MessageBubble.tsx` to import `ApiServiceError` and extract meaningful error messages from API responses:
     ```tsx
     } catch (err: unknown) {
       const errorMessage =
         err instanceof ApiServiceError
           ? err.message
           : err instanceof Error
           ? err.message
           : "Failed to record feedback. Please check your network.";
       onNotify?.(errorMessage, "error");
     }
     ```
  2. Configured the live backend daemon with network bypass on `127.0.0.1:8000`, ensuring browser clients can directly reach the FastAPI API without loopback restrictions.
- **Verification:**
  - **Thumbs Up:** Tested via live HTTP POST to `/api/feedback`. Returned HTTP 201 Created and `"Thank you for your feedback!"`.
  - **Thumbs Down:** Tested with negative feedback reasons (`"Outdated information"`) and comment (`"Fees was revised to 85,000."`).
  - **Duplicate Prevention:** When submitting feedback with the same `session_id` and `message_id`, the system successfully updated the existing record (`"is_updated": true`) rather than creating duplicates.
  - **Persistence:** Verified in `backend/app/data/student_feedback.json` across server restarts.
  - **Admin Integration:** Verified records are fully queryable and manageable under `/admin/feedback`.

### Change 4: Remove Top Blue Line from Exported PDF
- **Target File:** `frontend/src/utils/exportUtils.ts`
- **Previous Implementation:**
  ```ts
  const drawHeader = () => {
    // Decorative top strip
    doc.setFillColor(37, 99, 235);
    doc.rect(margin, yPos, contentWidth, 1.5, "F");
    yPos += 5;
  };
  ```
- **New Implementation:**
  - Removed `drawHeader()` and the `1.5mm` blue rectangle (`doc.setFillColor(37, 99, 235); doc.rect(...)`).
  - Adjusted initial vertical offset to `yPos = margin + 5` on the first page and within `checkPageBreak` for subsequent pages:
    ```ts
    const checkPageBreak = (neededHeight: number) => {
      if (yPos + neededHeight > pageHeight - margin - 10) {
        doc.addPage();
        yPos = margin + 5;
      }
    };

    // Initial Cover / Header Block (yPos initialized to margin + 5)
    yPos = margin + 5;
    ```
  - Preserved all other PDF formatting:
    - Title: `"SmartCollege AI"` in `#2563EB` font size 18pt.
    - Subtitle: `"Student Conversation Record & Verification Log"`.
    - Divider line: subtle `#E2E8F0` divider between header and metadata card.
    - Metadata card: Active Institution, Generation timestamp, total message count.
    - Message cards: Student queries in `#EFF6FF` with blue border, assistant answers in white with gray border.
    - Official source citation badges.
    - Footer pagination: `"Page X of Y"` and portal disclosure on every page.

### Change 5: Remove "Related verified questions" Section
- **Target Files:**
  - `frontend/src/components/MessageBubble.tsx`
  - `frontend/src/components/ChatWindow.tsx`
- **Previous Implementation:**
  - In `MessageBubble.tsx`, verified chatbot answers conditionally rendered a sub-card:
    ```tsx
    {isVerified && meta?.relatedVerifiedFaqs && meta.relatedVerifiedFaqs.length > 0 && (
      <Box sx={{ mt: 1.25 }}>
        <Typography variant="caption" color="text.secondary" fontWeight={600} display="block" sx={{ mb: 0.75 }}>
          Related verified questions:
        </Typography>
        <Stack direction="row" spacing={0.75} flexWrap="wrap" useFlexGap>
          {meta.relatedVerifiedFaqs.slice(0, 3).map((faq) => (
            <Chip key={faq.question} size="small" label={faq.question} onClick={() => onAskRelated?.(faq.question)} ... />
          ))}
        </Stack>
      </Box>
    )}
    ```
- **New Implementation:**
  - Completely removed the `Related verified questions:` label and question chips from `MessageBubble.tsx`.
  - Removed unused `onAskRelated` prop from `MessageBubbleProps` and `ChatWindow.tsx` to maintain 0 TypeScript compiler warnings (`noUnusedLocals`).
  - **Preserved Elements:**
    - The actual chatbot answer text.
    - Official source links and clickable labels (e.g., `Official Admissions Portal`).
    - Verification badges (`Verified Institutional Answer`, `Pending Institutional Verification`).
    - Last verified timestamp (`Last verified: 2026-11-11`).
    - Action row (Copy, Share, Thumbs Up, Thumbs Down).
    - Backend API `related_verified_faqs` schema and the 150 FAQ records.
